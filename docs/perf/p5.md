## Notes

**What "utterance end" means.** As in P4, the clock starts when the segmenter decides the utterance is over, 700 ms after
the last voiced frame. What the user feels is therefore about 0.7 s longer. "First audio" is when speech is handed to the
device, up to 60 ms (the device buffer) before it is heard.

**Where the time goes** (medians): transcription 0.42 s, first token 0.41 s, the rest of the first sentence about 0.1 s,
speech synthesis 0.4 s. All of it is the network. It varies by question: on its own, "What's the weather like in Paris
this weekend?" had p50 1.56 s over 7 app turns, above the p50 target, and 1.73 s over 5 turns of the debug test. Starting the
transcription before the 700 ms of trailing silence is over would cut the most, and is not done.

**Output device.** `IAudioClient::Initialize` takes about 300 ms here, so the output opens while the model is writing
(SPEC CHANGE §5.5). Closing it takes about 80 ms, after it is already silent.

**Binary +104 KB over P4** (2 072 576 → 2 177 024 bytes). No new crates; OneCore speech uses four more `windows` features.

**Offline voice.** OneCore (Microsoft Zira, 16 kHz) renders a short sentence in 40–170 ms and was played through the same path.
It uses no network, but this was not run with the network adapter disabled. Until P6, an offline voice turn still
fails at transcription; the offline voice steps in when only online speech fails or there is no key.

**Test quietness.** The app runs used `SOHI_DEV_QUIET` (speech at −48 dB), except for one offline word, so nobody has yet listened
to a whole spoken reply.
