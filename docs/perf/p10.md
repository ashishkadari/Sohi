# Perf report — P10 (longer memory and reminders)

Measured 2026-11-24 on the dev laptop (Windows 11 26300), one monitor. "MB" is decimal. A `dev-inject` test instance was
driven by messages to its own windows; speech was synthesized and injected.

| Metric | Measured | Budget | Result |
|---|---|---|---|
| idle CPU, never woken, no reminders | 16 ms in 45 s | ≤ 60 ms per 60 s | pass |
| idle CPU per 60 s, one reminder waiting, after 7 typed turns and one notice | 78 ms | ≤ 60 ms | **miss** (1 run) |
| memory then | private 7.7 MB, working set 34.8 MB | ≤ 20 MB; ≤ 27 MB (after voice turns only) | see below |
| memory with full mode open, after 12 typed turns | private 7.4–7.5 MB, working set 33.1–35.4 MB | ≤ 60 MB private | pass |
| first token in full mode, about 8 000 tokens of history (estimated) | 537–567 ms (last four turns) | none | |
| a due reminder → announced | under 1 s | none | |
| announced → first speech samples | 0.41–0.54 s (online), 0.23 s (offline) | none | |

## Working (live)

- Set by typing, by voice and in full mode; "again in 30 minutes" after an announcement; "every weekday at 9".
- Offline, with the command grammar: set, list and cancel; announced with the Windows voice.
- A reminder missed while Sohi was not running is announced after the start, once; a daily one moves on to tomorrow.
- In full mode the announcement is in the transcript; the Reminders button lists them.
- Memory: a number told before eight long messages was still known. With the old limit it would have been out of reach.

## Found and fixed on the way

- A reminder set while another one was waiting was never announced: dropping the old timer stopped the new one, which has
  the same id. The pill's 5-minute timer had the same fault.
- Models worked out wrong dates for weekdays, so they give the weekday's name and the calendar is done in code.

## Misses

- The 78 ms is one run; whether the waiting reminder has anything to do with it was not separated (its timer fires once
  in 10 minutes). 1.1.0 measured 16, 31 and 78 ms after use.
- The working set was measured after typed turns and the pill; the 27 MB budget is defined after voice turns only.

## Not tested

Whether the toast was seen (Windows accepted it); lock, sleep and full-screen cases; `speak = false`; the cost of the
three added tool descriptions per turn; a spoken reply's delay outside full mode was not measured again.

A sentence like "next Friday" may be read as this week's or next week's; Sohi says the date it set. The `persist` setting
under `[history]` still does nothing: the conversation ends with the program.
