the windows of a `dev-inject` test instance; speech was synthesized and injected. Start-up, idle and size rows are the
release build.

## Working

- Typed "full mode" and spoken "Full mode, um, full mode." open it; typed and spoken "exit full mode" close it.
- The window comes to the front and the pill goes away. Answers stream; Python code gets its own style (looked at in a screenshot).
- Esc during a reply stops the reply only. New chat clears the conversation.
- Leaving six times at different moments of the take-over: closed, no overlay left, no warnings.
- Reduced motion (forced in the config): opens within 0.4 s without an overlay, closes within 0.5 s.
- A tool question ("read your clipboard?") is asked in the window; Esc answers no and full mode stays open.
- The Copy code button copies exactly the code of the last block.

## Misses

- **Way back.** The cause was not investigated. The animation has only 44–47 frames, so three long ones set the p95.
- **Working set.** The 27 MB budget is defined after voice turns only. After full mode it is 29–33 MB. The
  cause was not measured; the text input DLLs that stay loaded are a candidate. Private bytes stay under 6.3 MB.
- **Idle CPU.** One run of eight is 62 ms. 1.0.0 measured 16, 31 and 16 ms just before, so a cause in P9 is not excluded,
  but the runs vary between 0 and 62 ms.

## Not tested

The tray menu entry; answering a tool question with yes or by voice in full mode; the shortcuts and `Shift+Enter` as real
key presses; locking or the display going off; monitor and DPI changes while it is open; Windows refusing the focus;
more than one monitor.

Long chats: the history keeps about 4 000 tokens, so long code answers are forgotten early.
